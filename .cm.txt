Work produced by three parallel agents on disjoint file sets, then integrated

=====================================================================
BUGS FOUND AND FIXED THAT THE AGENTS GOT WRONG
=====================================================================

1. The compat agent's verification suite had never run. `of()` takes one
   object keyed by slot, but all 23 call sites passed product ids
   POSITIONALLY, so `Object.entries("cpu-r5-5600")` produced [["0","c"],...]
   and the helper looked up a product with the id "c" and threw. Only the
   coverage and degradation sections had ever passed. Converted all 23 to
   explicit slot objects, inferring each slot from the product-id prefix
   because the omitted ids are not trailing (one call omits `gpu` from the
   middle), so a positional fix would have mis-slotted silently.

2. With the harness working, four rules looked broken. The cause was a second
   harness bug: `of()` returned references to the SHARED catalogue objects,
   and the hostile-input section does `p.specs = {...}` to prove nothing
   throws. That corruption leaked into every later section, so four working
   rules appeared dead. `of()` now clones, and a final assertion fingerprints
   the catalogue before and after to prove the script cannot mutate it.

3. `compat.biosUpdate` had a real bug the false failure exposed: `amdSeries()`
   used `/\b(\d{4})\b/`, which never matches `9800X3D` or `5600X` because `X`
   is a word character, so there is no boundary after the digits. The rule
   silently missed exactly the CPUs it exists for. Fixed to `/\b(\d{4})(?!\d)/`.

4. The perf card was still rendering the legacy coarse `notes` list while the
   new graded, resolution-aware `insights` sat unused behind a migration
   shim. The 13 `perf.ins.*` dictionary keys added in this commit were
   therefore dead code. Switched the card to `insights`.

5. The perf agent's own file `lib/algo/optimizer.ts` prints finding KEYS
   rather than prose. Checked: it is only reachable from the admin console and
   an API route, never a public page, so keys-over-prose is correct there.

6. The UX agent reported mojibake in three French files. It was a
   console-encoding artifact: a full scan for U+251C and U+FFFD across every
   source file found ZERO. The `Intel®` hits are real trademarks and `â` is
   real French ("câble"). Those files were not touched.

=====================================================================
COMPATIBILITY ENGINE
=====================================================================
`checkCompat` no longer returns English sentences. It returns
`{ key, vars, severity }` findings, where `key` is a stable dictionary key.
This fixes a real bug: the FRENCH builder was rendering English warnings
("BLOCK: CPU needs DDR4, RAM is DDR3") because the strings were assembled
inside the module and printed raw. 16 rules across block / warn / info, with
`result.counts` for a three-state banner.

New rules: cooler-under-TDP-sizing, RAM-too-fast-for-the-CPU, VRM entry-level,
BIOS support, PSU efficiency at load, PSU overkill, and 16-pin cable clearance
(which interpolates the required slack because a 16-pin card needs 35 mm of
bend versus 20 mm for side-connectors). `psuOverkill` and `psuLowEfficiency`
are provably disjoint and there is now a test sweeping all 40x77x79 PSU/CPU/GPU
triples asserting the contradiction can never occur.

Performance model is now resolution-aware (1080p and 1440p scored separately,
since a CPU-bound 1080p build is GPU-bound at 1440p), grades bottlenecks mild /
significant / severe per side, and adds an upgrade-path insight naming the one
part whose replacement would move the score most.

`scripts/check-perf.cjs` is the verification harness: 63/63 passing, exit 0,
covering benchmark-key coverage against the real catalogue, safe degradation
on empty/hostile specs, known-good and known-bad builds with exact key-set
assertions, no dead rules, score range and monotonicity over 6083 builds, and
a catalogue-mutation fingerprint. `scripts/dump-keys.cjs` derives the
dictionary key table from the code so it cannot drift.

=====================================================================
MY OWN REGRESSION, FOUND AND FIXED
=====================================================================
The language flip moved English to the root, but the llms.txt GEO endpoints are
template strings rather than `href=` attributes, so the automated href rewrite
never touched them. Both halves were pointing at the wrong URLs:

- /llms.txt advertised ${base}/en/... so every link 308-redirected
- /fr/llms.txt advertised UNPREFIXED ENGLISH urls, i.e. the wrong language
- both "French version of this file" pointers aimed at themselves

These are what GPTBot, ClaudeBot and PerplexityBot read to discover the site.
Verified after the fix: 433 English URLs all return 200 with no redirect hop,
and all 432 French URLs are /fr/*. Also fixed /en/builder in the builder's
openGraph.url.

Added lib/seo/jsonld.ts and wired it into both layouts. JSON.stringify does
not escape "<", and this site's JSON-LD embeds scraped merchant text, so a
listing named "Foo </script><script>..." would break out of the tag and
execute. That is stored XSS from untrusted crawler input, not theoretical.
